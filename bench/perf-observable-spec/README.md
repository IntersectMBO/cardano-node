# Cardano node performance observability

A specification of the events a Cardano node implementation has to emit so that its performance can be analysed by the Cardano benchmarking workbench (`locli`), and compared to other implementations under identical workloads. It defines the *semantics* of each observable (the precise moment it marks, and what its payload means), and a canonical *syntax* for the parts that have to match exactly across implementations, block hashes above all.

**Status:** draft 0.1 (2026-11-04). The source of truth is [`perf-observable-spec.typ`](perf-observable-spec.typ); this README only summarises it.

## Summary

- **Conformance tiers:** 1 core (block production and diffusion, resources), 2 forging breakdown, 3 workload and ledger, R runtime-specific (GC metrics).
- **Log format:** JSON lines with a fixed envelope (`at`, `ns`, `sev`, `thread`, `host`, `data`) and precisely defined basic types (timestamps, points, full-length block hashes, durations in seconds, sizes in bytes).
- **Emission requirements:** no sampling or rate limiting, complete hashes, timestamps taken at the emission point.
- **Observable catalogue:** 25 namespaces across resource sampling, forge loop, block diffusion, chain selection, ledger, and transaction intake/mempool, each with emission point, payload and derived metrics.
- **Ordering invariants and derived metrics:** what can be checked mechanically on any log, and how the workbench report metrics are computed.
- **Deviations of the Haskell node:** where cardano-node 11.2.0 differs from the canonical form, syntactically (S1–S8) and semantically (E1). Other implementations follow the specification, not the deviations.

## Files

These files currently only exist on branch `mkarg/observability-spec`, not yet on `master`.

- [`perf-observable-spec.typ`](perf-observable-spec.typ): the specification.
- [`template/`](template/): the document design, derived from the MIT-licensed Typst template basic-report 0.5.0, with the ICAN Group palette and typefaces (`brand.typ`).
- [`schema/`](schema/): JSON Schema (draft 2020-12) for the envelope, the basic types, and each observable's payload. `observables.schema.json` is generated by `tools/gen_observables.py`.
- [`examples/canonical.jsonl`](examples/canonical.jsonl): one real event per observable, in canonical form (provenance: appendix A of the specification).
- [`tools/validate.py`](tools/validate.py): validates a log stream against the schemata, reporting per namespace which events deviate and how.

## Building the PDF

```bash
typst compile perf-observable-spec.typ
```

This writes `perf-observable-spec.pdf`, which isn't tracked in git. The first build downloads the `@preview/hydra` package. The document uses the ICAN Group design (`template/`). Its typefaces, Space Grotesk, Inter and IBM Plex Mono, are used where installed (static font files; Typst doesn't support variable fonts well); otherwise Typst warns about each missing font and falls back to Inter or DejaVu Sans / DejaVu Sans Mono.

## Validating a log

Requires the Python packages `jsonschema` (4.18 or later) and `referencing`; the latter is a dependency of the former, so `pip install jsonschema` suffices.

```bash
python3 tools/validate.py schema <log.jsonl>
```
