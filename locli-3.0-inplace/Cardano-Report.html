generateTypstReport :: forall (f :: Type -> Type) (g :: Type -> Type). (KnownCDF f, KnownCDF g) => FilePath -> Maybe FilePath -> [Metadata] -> Summary g -> ClusterPerf -> BlockProp f -> IO Text Source #

The single-run report: bundles the single table files (as written by the workbench's single-run analysis) found next to the report, by importing them. Missing table files are noted in the report, instead of failing its compilation. With a Plutus workload calibration CSV, it's rendered as an addendum. For a variance report (the results of summariseMultiSummary & co.), the input runs are given, and listed on the title page and in the Manifest.

fieldsWarnIfZero :: [FieldName] Source #

Metrics whose value 0 most likely indicates a problem (e.g. trace parsing), not a measurement: their cells are rendered as a warning.

fieldsZeroIsUnreported :: [FieldName] Source #

Metrics that can't be zero over a whole run if they're measured: a 0 there means the node didn't report the field (optional in the observability spec), so it renders as not available. A running node always does network I/O and writes to storage; the GC fields are only reported by a managed runtime. Not storage reads: with its data in the page cache, a node can read nothing from storage throughout.
